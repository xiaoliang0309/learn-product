微服务远程调用（Nacos + Feign）

本页面是服务A（learning-mct-api, 9090）。点按钮后，服务A 不查自己的数据库， 而是通过 Feign 按服务名去 Nacos 找服务B（merchant-service-b, 9095），远程调用它拿数据。
链路：服务A → Feign → Nacos 查地址 → 服务B → 返回

验证降级（fallback）

把服务B 停掉（关掉它的进程），再点上面的按钮，会走 fallback 降级， 返回兜底提示「调用商户服务失败」，而不是直接报错——这就是微服务的容错。

Elasticsearch 全文搜索 vs MySQL LIKE

Elasticsearch 是专用的搜索引擎，和 MySQL 的 LIKE 相比：
· MySQL LIKE：只能从前往后匹配，且全表扫描慢
· ES 全文搜索：倒排索引，支持分词、模糊、高亮，海量数据也快
· qingo 用 ES 存储订单数据（doc_mct_order 索引），支持按商户/店铺/状态/商品名搜索

数据双写：MySQL（主数据） + ES（搜索副本）

核心思想（对齐 qingo）：下单时同时写两份——
· MySQL = 主数据，保证业务正确（事务、精确查询）
· ES = 搜索副本，保证搜索快（倒排索引、模糊搜索、聚合）
· ES 的 id = MySQL 的自增 id，两边靠 id 对齐
· 搜索走 ES，详情走 MySQL；不一致时用「同步」把 MySQL 刷到 ES 修正

配置中心：配置放网页上管，改完不用重启就生效

核心思想（对齐 qingo）：把「会变的配置」从代码搬到 Nacos 配置中心统一管理。
· 没用配置中心：改配置 → 改 application.yml → 重新打包 → 重启项目才生效
· 用了配置中心：改配置 → Nacos 网页改 → 点发布 → 不重启立刻生效
· 关键注解：@RefreshScope（类上，自动刷新） + @Value("${key:默认值}")（读配置）

📖 动手试：
1️⃣ 先点下面「查看当前配置」，记下 orderMaxAmount 的值
2️⃣ 打开 Nacos 控制台（nacos/nacos）→ 配置管理 → 配置列表 → 编辑 overseas-learning.yaml
3️⃣ 把 max-amount 改成别的数（比如 12345）→ 点「发布」
4️⃣ 不重启项目，再点「查看当前配置」→ 值变了！这就是动态刷新

配置是怎么读进来的

三步：
① Nacos 上写 YAML 配置（树状缩进）
② Java 定义字段 + @Value("${点号路径:默认值}") 读出来
③ @RefreshScope 让改动不用重启就生效

对应关系（YAML 每层缩进 = @Value 里一个点号）：
learning.order.max-amount ←→ @Value("${learning.order.max-amount:100000}")

Nacos 上的配置（overseas-learning.yaml）
learning:
  features:
    cooling-reminder: false
  order:
    max-amount: 66666
  tips:
    welcome: 这是来自 Nacos 的文案
Java 读取（LearningBizConfig.java）
@RefreshScope
public class LearningBizConfig {
  @Value("${learning.features.cooling-reminder:true}")
  private Boolean coolingReminder;
  @Value("${learning.order.max-amount:100000}")
  private Long orderMaxAmount;
  @Value("${learning.tips.welcome:默认文案}")
  private String welcomeTip;
}
